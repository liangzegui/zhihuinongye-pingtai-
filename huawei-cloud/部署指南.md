# 华为云无服务器部署指南

## 架构概览

```
ESP32 ←→ (MQTT) IoTDA → (HTTP推送) FunctionGraph → (写入) RDS MySQL
                          ↑                    ↓
Vue前端 → (HTTPS) API Gateway ← (绑定) FunctionGraph
```

---

## 第一步：创建RDS MySQL数据库

### 1.1 登录华为云控制台

访问：https://console.huaweicloud.com/rds/

### 1.2 创建MySQL实例

1. 点击 **购买数据库实例**
2. 选择配置：

| 配置项 | 值 |
|--------|-----|
| 数据库引擎 | MySQL |
| 版本 | 8.0 |
| 实例规格 | 最小规格（测试用）或2核4G |
| 存储空间 | 40GB |
| 网络 | 选择VPC（建议与FunctionGraph同VPC）|

3. 设置管理员密码（记住！）
4. 完成购买

### 1.3 初始化数据库

1. 在RDS控制台进入 **数据库管理**
2. 使用**SQL查询**或连接工具执行 `database/schema.sql`
3. 验证表已创建：`SHOW TABLES;`

### 1.4 获取连接信息

记录以下信息（后续配置FunctionGraph使用）：
- **内网地址**：如 `192.168.0.100`
- **端口**：3306
- **数据库名**：agri_db
- **用户名**：root
- **密码**：您设置的密码

## 第二步：创建FunctionGraph函数

### 2.1 创建数据接收函数

1. 访问：https://console.huaweicloud.com/functiongraph/
2. 点击 **创建函数**
3. 配置：

| 配置项 | 值 |
|--------|-----|
| 函数名称 | `receive-iotda-data` |
| 运行环境 | Python 3.9 |
| 函数类型 | HTTP函数 |

4. 复制 `functiongraph/receive_iotda_data.py` 内容到代码编辑器
5. 配置环境变量：

```
DB_HOST=您的RDS内网地址
DB_PORT=3306
DB_USER=root
DB_PASSWORD=您的RDS密码
DB_NAME=agri_db
```

6. 配置依赖：在 **依赖包** 中添加 `pymysql`

7. 点击 **部署**

8. 创建 **HTTP触发器**，记录触发URL（如 `https://xxx.apig.cn-south-1.huaweicloudapis.com/xxx`）

### 2.2 创建设备控制函数

1. 再次点击 **创建函数**
2. 配置：

| 配置项 | 值 |
|--------|-----|
| 函数名称 | `control-device` |
| 运行环境 | Python 3.9 |
| 函数类型 | HTTP函数 |

3. 复制 `functiongraph/control_device.py` 内容到代码编辑器
4. 配置环境变量：

```
IOTDA_ENDPOINT=https://iotda.cn-south-1.myhuaweicloud.com
IOTDA_PROJECT_ID=您的项目ID（在"我的凭证"中查看）
IOTDA_AK=您的AccessKey
IOTDA_SK=您的SecretKey
DEVICE_ID=69568516c00ccb6d4b302187_esp32-001
```

5. 配置依赖：添加 `requests`

6. 点击 **部署**

7. 创建 **HTTP触发器**，记录触发URL

---

## 第三步：配置IoTDA数据转发

### 3.1 登录IoTDA控制台

访问：https://console.huaweicloud.com/iotdm/

### 3.2 创建数据转发规则

1. 进入 **规则** → **数据转发**
2. 点击 **创建规则**
3. 配置：

| 配置项 | 值 |
|--------|-----|
| 规则名称 | `forward-sensor-data` |
| 触发事件 | **设备属性上报** |
| 产品/设备 | 选择您的ESP32设备 |
| 转发目标 | **HTTP推送** |
| **URL** | `receive-iotda-data` 函数的HTTP触发URL |
| 请求方式 | POST |

4. 点击 **启用**

---

## 第四步：配置API Gateway

### 4.1 创建API分组

1. 访问：https://console.huaweicloud.com/apig/
2. 点击 **创建API分组**
3. 配置：

| 配置项 | 值 |
|--------|-----|
| 分组名称 | `agri-api` |
| 域名 | 自动生成或自定义 |

### 4.2 创建控制API

1. 进入分组 → **API管理** → **创建API**
2. 配置前端定义：

| 配置项 | 值 |
|--------|-----|
| API名称 | `control-device` |
| 请求协议 | HTTPS |
| 请求方法 | POST |
| 请求路径 | `/api/device/control` |
| 安全认证 | IAM认证（推荐）或APP认证 |
| 跨域 | 启用CORS |

3. 配置后端定义：

| 配置项 | 值 |
|--------|-----|
| 后端类型 | **FunctionGraph** |
| 函数 | 选择 `control-device` |
| 超时时间 | 30000ms |

4. 点击 **立即创建**
5. **发布** API

### 4.3 创建查询API（可选）

同样步骤创建：
- **GET** `/api/device/status` - 查询设备状态
- **GET** `/api/data/latest` - 获取最新数据
- **GET** `/api/data/history` - 获取历史数据

## 第五步：测试完整流程

### 5.1 测试数据上报

1. ESP32上电并连接WiFi和IoTDA
2. 查看FunctionGraph日志：
   - 进入 `receive-iotda-data` 函数
   - 点击 **日志** 标签
   - 应该看到 "收到IoTDA推送" 和 "数据已保存到数据库"

3. 查询RDS数据库：
```sql
SELECT * FROM t_env_data ORDER BY collect_time DESC LIMIT 10;
```

### 5.2 测试设备控制

使用Postman或curl测试：

```bash
curl -X POST https://您的APIG域名/api/device/control \
  -H "Content-Type: application/json" \
  -d '{
    "pump": true,
    "manual": true
  }'
```

应返回：
```json
{
  "message": "控制命令已下发",
  "properties": {
    "pump": true,
    "manual": true
  }
}
```

ESP32应收到MQTT下发并执行控制。

## 第六步：前端对接

### 6.1 修改前端API配置

在 `.env.production` 中设置：

```
VUE_APP_API_BASE_URL=https://您的APIG域名
```

### 6.2 前端调用示例

```javascript
// api/device.js
import axios from 'axios'

const BASE_URL = process.env.VUE_APP_API_BASE_URL

// 控制设备
export function controlDevice(data) {
  return axios.post(`${BASE_URL}/api/device/control`, data)
}

// 使用
controlDevice({
  pump: true,
  fan: false,
  manual: true
}).then(res => {
  console.log('控制成功', res.data)
})
```

## 常见问题

### Q1: FunctionGraph无法连接RDS

**解决**：
1. 确保FunctionGraph和RDS在同一VPC
2. 在RDS安全组中放行FunctionGraph的出网IP
3. 使用RDS的**内网地址**

### Q2: IoTDA推送失败

**解决**：
1. 检查数据转发规则是否启用
2. 查看FunctionGraph日志是否有报错
3. 确认HTTP触发URL正确

### Q3: 前端调用API 403/401

**解决**：
1. 在APIG中启用CORS
2. 如果使用IAM认证，需要在前端添加签名
3. 或改用APP认证并在前端Header中携带AppCode
